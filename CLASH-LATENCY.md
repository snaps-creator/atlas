## Изменено в Atlas

Ручная проверка списка и отдельного сервера: один запрос к Mihomo
`/proxies/{encoded-name}/delay`, URL `http://cp.cloudflare.com/generate_204`,
timeout 10000 мс, без expected-status, без переключения на другие URL.
Время берётся из ответа ядра; unified-delay уже был включён.
До десяти параллельных запросов, запуск работников разнесён на 20 мс.
Clash использует случайную небольшую задержку; Atlas — детерминированную.
Общий UI deadline зависит от числа волн по десять серверов, а не фиксирован на 18 с.
Ошибки IPC/API не превращаются в таймаут узла. История других тестовых URL
не перезаписывает эти измерения. Нулевая измеренная задержка сохраняется как 0 мс.

Это измерение HTTP-задержки, не ICMP ping и не пропускная способность.
HTTP-ответ с ошибочным статусом может дать задержку, как в Clash.
Строгие HTTPS/204-проверки восстановления и AUTO сохранены отдельно: число
в карточке само по себе не является разрешением автоматического переключения.

Ранее Atlas массово проверял HTTPS www.gstatic.com за 5 секунд через группу.
Эти отличия могут давать другую картину доступности; скриншоты сами по себе
не доказывают, что все расхождения вызваны только методикой теста.
Равенство узлов, сетевого пути и одновременных измерений ещё необходимо для A/B.

Проверка: настоящий bundled Mihomo/VLESS, специальные символы в имени,
HTTP 503 как измерение задержки и отказ строгой проверки, HTTP 404 как ошибка,
массовая проверка 13 элементов с успешным узлом после неуспешных.
Работающая установка Atlas не обновлена и не перезапущена.
