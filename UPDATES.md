# Обновления Atlas через GitHub Releases

Текущая версия проекта: **Beta 15.1** (`1.0.0-beta.15.1`).

Beta 15.1 включает исправление DHCP и доступа к частной IPv4-сети, переключение
серверов без перезагрузки TUN, отдельные фоновые проверки задержки, восстановление
после сбоя ядра и изменения маршрутов, а также ограничение ожидания выхода.
Проверки и ограничения описаны в `RECOVERY-VALIDATION.md` и
`OFFICE-NETWORK-VALIDATION.md`. Многосуточные испытания ещё не выполнены.

Номер версии повышен во всех манифестах. После merge GitHub Actions должен
опубликовать новый подписанный релиз `v1.0.0-beta.15.1`. Merge сам по себе
не означает, что установщик и `latest.json` уже опубликованы.

В Beta 14.5 добавлены режимы «Правила / Глобальный / Прямой» над статистикой,
график трафика за 10 минут и проверка ChatGPT, Grok, Gemini, YouTube, Telegram.
Подробности поведения и локальных проверок — в `DASHBOARD.md`.

Для выпуска через GitHub локальная установка Rust не обязательна: workflow
сам устанавливает инструменты на Windows runner. Загрузите изменённые исходники
через PR и выполните merge в `main`. Прямой push в `main` также запускает выпуск.
Дождитесь успешного `Publish Atlas update`: только после него новый установщик,
его подпись и `latest.json` считаются готовыми. Секреты подписи должны быть
настроены в GitHub Actions; наличие этих секретов локально не проверено.
Файлы `Atlas Beta 14.4 Setup.exe` в корне — предыдущая версия.
`Atlas Beta 14.5 Setup.exe` — старая локальная сборка для ручной установки,
без подписи updater. Для автоматического обновления используйте подписанные
артефакты GitHub Actions.

Atlas проверяет GitHub при запуске и затем каждые **6 часов**. Запрос имеет
тайм-аут 15 секунд; проверки не выполняются параллельно. Ошибка не мешает
работе приложения: следующая попытка происходит через 6 часов. После обнаружения
обновления опрос прекращается до перезапуска, чтобы не заменять скачиваемый пакет.
Установка начинается только по кнопке «Обновить». Проверка защиты каждые
30 секунд — отдельная функция, она не обращается к GitHub Releases.

Раздел «Обновления» в боковом меню показывает установленную версию, время и
результат последней проверки. Кнопка «Проверить обновления» запускает тот же
запрос вручную, в том числе повторно после ошибки. Ручные и фоновые запросы
не выполняются параллельно. При обнаружении новой версии вместо номера версии
внизу боковой панели появляется «Обновить»; скачивание и установка показываются
в разделе «Обновления». Пока пакет доступен, повторный поиск отключён.

## Однократная настройка GitHub

Закрытый ключ создан локально и не входит в Git:

```text
C:\Users\nikid\.tauri\atlas-updater.key
C:\Users\nikid\.tauri\atlas-updater.password.txt
```

В репозитории GitHub откройте **Settings → Secrets and variables → Actions**,
создайте секрет `TAURI_SIGNING_PRIVATE_KEY` и вставьте в него полное содержимое
файла `atlas-updater.key`. Создайте секрет
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` с содержимым файла
`atlas-updater.password.txt`. Публичный ключ уже находится в
`src-tauri/tauri.conf.json`.

Репозиторий и его Releases должны быть публично доступны: клиент обращается к
`releases/latest/download/latest.json` без GitHub-токена.

## Публикация обновления

1. Обновите SemVer одновременно в `package.json`, `src-tauri/Cargo.toml` и
   `src-tauri/tauri.conf.json`.
2. Обновите соответствующие версии в `package-lock.json` и `src-tauri/Cargo.lock`.
   Название в интерфейсе и заголовке окна формируется автоматически из версии приложения.
3. Создайте Pull Request и дождитесь успешной проверки **Check pull request**.
4. Выполните merge в `main`. Публикация начнётся автоматически после merge.

Workflow запускает тесты, собирает NSIS-установщик, подписывает пакет обновления
и публикует GitHub Release вместе с `latest.json` и `.sig`. Закрытый ключ и
GitHub-токен в приложение не встраиваются.

Подпись updater подтверждает целостность обновления внутри Atlas. Для удаления
сообщения Windows «Неизвестный издатель» нужен отдельный Authenticode-сертификат
издателя; ключ updater его не заменяет.

Pull Request запускает только тесты и проверку production-сборки. У него нет
права записи в репозиторий, поэтому он не создаёт tag или Release. Перед каждым
следующим merge с публикацией обязательно увеличьте версию: повторно использовать
существующий tag workflow не позволит.
