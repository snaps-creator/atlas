# Обновления Atlas

В 2.5.1 единый офлайн-установщик `Atlas-Setup-2.5.1.exe` распространяется только через [GitHub Releases](https://github.com/snaps-creator/atlas/releases/latest). Релиз пока не опубликован; кандидат хранится во временных Actions artifacts. ZIP исходников не является дистрибутивом. Публикация требует ручного запуска после merge и отдельного разрешения.


## Alpha 2.3.2

- Повторное подключение после `CleanupError` заново проверяет фактическую очистку. Историческая ошибка остановки сохраняется в диагностике, но не блокирует повторную попытку при подтверждённом освобождении службы, процессов, прокси и маршрутов.
- Классификация Atlas-TUN общая для приложения, службы и AtlasMaintenance. Неизвестный драйвер отличается от чужого; исчезнувшая запись реестра больше не дополняется разным кешем в разных процессах. Выключенный интерфейс без маршрутов не объявляется занятым. Неизвестные адаптеры не удаляются.
- Сбой канала отделён от состояния процесса SCM. Живая служба принимает повторное подключение того же владельца в ограниченном окне; незавершённые изменяющие команды автоматически не повторяются.
- Новая конфигурация сначала проверяется отдельным ядром без TUN. При применении прежние YAML, селектор и Xray сохраняются до проверки пути; запись `last-working` выполняется после проверки. Неуспешный откат завершает принадлежащую Atlas сессию и запускает существующий путь очистки.
- Автоматическое повторное подключение ограничено пятью неудачными попытками. Ручная попытка остаётся доступна и заново проверяет состояние.
- Ошибки HTTPS, credentials, отсутствующего host, fragment и некорректного URL подписки разделены; диагностический код не содержит секретной ссылки.
- Публикация установщика проходит проверку обновления с активным TUN, повторного открытия TUN и восстановления IPC без изменения PID службы. Подробности доказательств и ограничений: [NETWORK-RECOVERY.md](NETWORK-RECOVERY.md).

## Alpha 2.2.5

- Обновление скачивается и проверяется с работающим подключением. Передача установщику больше не зависит от успешного `disconnect` старого приложения.
- Новый `AtlasMaintenance.exe` извлекается из подписанного установщика до замены файлов. Он не зависит от CEF или старого Atlas: проверяет принадлежность службы и процессов каталогу установки, завершает их, проверяет освобождение TUN, удаляет маршруты выключенного подтверждённого адаптера Atlas и восстанавливает принадлежащие Atlas настройки прокси. При неустранённой ошибке файлы не заменяются.
- Установка поверх старой версии двойным щелчком направляется в тот же режим обновления, чтобы не вызывать старый деинсталлятор. Удаление новой версии тоже использует независимый модуль очистки.
- Исправлена ложная блокировка выключенного адаптера `Meta Tunnel`: принадлежность Wintun определяется по GUID/PnP и службе драйвера, а не по слову в отображаемом названии. Активный или неизвестный адаптер не считается очищенным.
- Версии до 2.2.5 уже содержат прежнюю команду отключения в обновляющем интерфейсе. Если она блокирует обновление, первый переход выполняется новым полным EXE поверх установленной версии; переписать этот код внутри уже работающего старого приложения публикацией манифеста невозможно.

## Alpha 2.2.4

- Исправлен воспроизведённый разрыв длительных TCP/WebSocket-потоков при замене конфигурации Xray. Раньше старый процесс завершался сразу после применения настроек, хотя через него ещё шёл трафик.
- Изменение правил и выбора сервера при неизменных настройках Xray сохраняет его процесс и локальные SOCKS-порты. При изменении самих серверов новые подключения идут через новую конфигурацию, существующие заканчивают работу через прежнюю.
- Неиспользуемые прежние процессы освобождаются по таблице TCP Windows с проверкой PID и принадлежащих им портов. При выходе все поколения процессов получают остановку вместе; число одновременно сохраняемых поколений ограничено без принудительного обрыва живых потоков.
- Добавлены проверки одного непрерывного потока через настоящие Mihomo и Xray: выбор сервера, повторное применение конфигурации, добавление узла, сохранение активного потока, освобождение завершённого и остановка приложения с активными старыми соединениями. Проверки работают только на loopback, без TUN и изменения сети компьютера.

## Alpha 2.2.3

- Исправлена проверка владельца сетевой сессии: наблюдатель из Atlas.Service.exe проверяет Atlas.exe в той же папке установки, а не ошибочно сравнивает путь окна с собственным EXE службы.
- Ошибка запуска наблюдателя передаётся в интерфейс и историю диагностики до закрытия канала, с сохранением исходной причины.
- Приёмка установщика дополнена проверкой идентификации настоящих упакованных Atlas.exe и Atlas.Service.exe без запуска VPN/SCM. Регрессионные тесты проверяют также отказ чужому одноимённому EXE из другой папки и доставку ошибки через настоящий named pipe.


## Alpha 2.2.2

Объединяет изменения 2.1.4 и 2.2.1: отступы интерфейса, очистку перед обновлением, ограниченное ожидание завершения сетевой сессии и завершение принадлежащих ей процессов.

- Исправлен пустой серый экран: восстановлен штатный вход в процессы CEF без обязательного самостоятельного присоединения к дополнительному Windows Job. Владение сетевыми ядрами и наблюдение за службой сохранены.
- Найденное обновление больше не останавливает дальнейшие проверки. Можно получить последнюю версию без установки промежуточной; непосредственно перед скачиванием адрес обновления проверяется заново.
- Во время скачивания предложение не заменяется фоновым опросом.
- Перед публикацией проверяется фактическая отрисовка React и IPC из упакованного приложения, затем отсутствие оставшихся процессов. Режим проверки не запускает VPN и не изменяет пользовательские настройки.
- Канал latest переключается только после загрузки EXE, подписи и манифеста.

- Служебные суффиксы идентификаторов скрыты в названиях серверов; выбор, избранное и пинги сохраняют независимость.
- Исторический автономный комплект для ZIP исходников удалён в 2.5.1; установщики больше не хранятся в Git.

## Alpha 2.1.2

- Выбор сервера сохраняет пинги остальных узлов и не отменяет их проверки.
- Ручной выбор подтверждается локальным ядром; внешние проверки выполняются фоном.
- Независимое обновление подписок при запуске, по расписанию и при обнаруженных сбоях; время успешного обновления на каждой карточке.
- Повторные проверки карантинных узлов и сохранение результатов неизменившихся серверов.
- Закрытие соединений ядра перед штатным освобождением TUN.
- Штатная очистка TUN перед завершением ядра; согласованные сроки ожидания службы.
- Сохранение этапов завершения и их длительности в диагностике.
- Исторический второй контроль Cloudflare заменён в 2.5.1 независимым HTTPS-контролем Google generate_204; ожидается точный HTTP-статус.
- Реальные DNS-ответы для проверок Windows NCSI вместо синтетического IPv4.
- Исправлена кодировка вывода системных утилит и классификация DNS-ответов без адреса.
- Выровнена кнопка сохранения пароля локальной диагностики.

Версия исходников: **Alpha 2.1.2** (`2.1.2-alpha.1`). CI присваивает публикации уникальный номер сборки, сохраняя обозначение 2.1.2.

Подписанный установщик и `.sig` доступны в GitHub Releases после успешной публикации.
Для проверки скачанной пары укажите путь к EXE:

```powershell
node scripts/verify-installer.cjs "путь-к-установщику.exe"
```

Подпись updater проверяется публичным ключом из `src-tauri/tauri.conf.json`.
Она не является Authenticode-подписью издателя Windows.

## Выпуск

1. Синхронно изменить версию в package.json, package-lock.json, Cargo.toml,
   Cargo.lock и tauri.conf.json.
2. Создать PR. Check pull request выполняет тесты и проверяет сборку интерфейса.
   Build signed PR installer для веток этого репозитория собирает и подписывает
   установщик; форки не получают доступ к ключу.
3. Подписанный установщик PR доступен в артефакте `atlas-signed-installer`.
   Для обычного PR добавлять бинарные файлы в Git не требуется.
4. После merge в main workflow Publish Atlas update собирает подписанный Release
   с установщиком, SIG и latest.json. Merge сам по себе не означает завершение выпуска.

Для подписи в GitHub Actions используются существующие секреты
TAURI_SIGNING_PRIVATE_KEY и TAURI_SIGNING_PRIVATE_KEY_PASSWORD. Публичный ключ
нельзя менять без отдельного плана миграции установленных клиентов.

Пользователь скачивает актуальный установщик из GitHub Releases после успешного выпуска. Встроенный updater обращается к
`releases/latest/download/latest.json`, а не к EXE в исходниках.

Atlas проверяет обновления при запуске и каждые шесть часов. Ручная проверка —
в разделе «Обновления»; установка начинается по кнопке пользователя. Для выпуска
следующей версии нужно повысить номер: уже опубликованный tag повторно не выпускается.
