# Источники подписок URL / VLESS

Реализация использует существующие Subscription, Settings, загрузчик, SQLite/Windows Credential Manager, выбор, Core и штатное отключение. Отдельного VLESS-клиента или сетевого lifecycle нет.

## Модель и совместимость

- `Subscription.source`: `URL` либо `VLESS`. Старые записи без поля остаются URL, независимо от протоколов внутри них. Существующие HTTPS-подписки автоматически не перераспределяются.
- `Settings.activeSource` сохраняется вместе с настройками. `sourceSelections` хранит выбор каждой группы, `selected` — текущий выбор для существующего ядра.
- `Settings.servers()` и `active_subscriptions_mut()` ограничивают подготовку конфигурации активной группой, включая подготовку Xray. Неактивный Xray не запускается.
- Список, ошибка, время обновления и refresh lease остаются у существующей подписки. Каждая операция обновляет исходный ID/source, даже если во время download пользователь сменил группу.
- URL принимает HTTPS-подписки прежних поддерживаемых форматов. VLESS принимает HTTPS-подписки и одиночные ключи; узлы другого типа пропускаются с диагностикой. Данные другой группы сохраняются.
- При обновлении имена одинаковых конфигураций сохраняются независимо от порядка; повторные конфигурации исключаются. Удалённый выбранный узел переводит выбор в AUTO своей группы. Пустая группа не использует серверы соседней.

## Переход

UI вызывает отдельную команду `subscription_source`. Общий `save` не может изменить activeSource или подменить список подписок.

1. До ожидания command mutex существующий settings-change guard отменяет незавершённую попытку connect и блокирует автоматическое возобновление.
2. Под command mutex, если источник действительно другой, вызывается штатный `disconnect()`.
3. Этот вызов отключает reconnect intent и проходит существующее восстановление owned core/service, TUN baseline, маршрутов и proxy. Ошибка оставляет прежний источник и CleanupError; переключение не продолжается.
4. Только после успешного отключения восстанавливается сохранённый выбор целевой группы. Настройки сначала сохраняются в Store, затем публикуются в памяти. Ошибка записи оставляет прежний источник в отключённом состоянии.
5. Новый источник остаётся Disconnected; автоматического connect из команды переключения нет. Последующие подключения используют обычную команду connect.

UI блокирует повторное переключение до ответа, разрешает запрос смены во время текущего подключения/отключения, учитывает несколько параллельных UI операций счётчиком. Устаревший ответ с меньшей revision не возвращает старую группу на экран. Backend сериализует изменения; повторный запрос уже активного источника идемпотентен.

## Проверки 7 октября 2026

Подтверждено:

- Миграция legacy → URL, сохранение активного источника, отдельного выбора, отсутствие fallback в пустую группу.
- Изменения/ошибки неактивной подписки не меняют сгенерированную сетевую конфигурацию активной.
- URI/Base64/mixed subscription, ошибочные VLESS-узлы, дедупликация и стабильные имена при перестановке.
- Полный backend suite: 187 passed, 1 opt-in live test ignored; maintenance: 17 passed.
- Frontend: 39 passed, production build успешен. Зависимости синхронизированы через npm ci с lockfile.
- Opt-in live test выполнен отдельно с предоставленным пользователем ключом: настоящий HTTPS publisher на loopback → штатный HTTPS downloader/Base64 parser → общая модель → встроенные Mihomo/Xray → внешний HTTPS через REALITY. Обновление, encrypted SQLite save/load, остановка/повторный запуск, URL → VLESS → URL → VLESS с запоминанием выбора прошли.
- Реальные TCP, WS, gRPC, HTTPUpgrade, XHTTP, KCP проверяются существующим loopback integration test с настоящим Xray сервером; это не проверка публичных TLS-серверов для каждого транспорта.
- Визуально проверен настоящий компонент переключателя: URL/VLESS, пустое состояние, заблокированное ожидание. Браузерный компонентный стенд не эмулирует VPN и не доказывает desktop integration.

**Граница доказательства:** live test работает через изолированные loopback proxy-порты, не меняет системные маршруты и не устанавливает службу. Он не доказывает отсутствие остаточных DNS/routes/TUN после переключения установленного приложения с активным системным VPN. Полный критерий системного переключения требует отдельной Windows-приёмки; утверждать, что вся матрица ниже уже пройдена, нельзя.

## Windows-приёмка перед выпуском

На отдельной Windows VM с установленным кандидатом и реальными тестовыми подписками:

| Сценарий | Требуемое наблюдение |
|---|---|
| Старт URL и VLESS | Последняя группа и её выбранный сервер; чужие узлы не в config/controller |
| URL → VLESS и обратно без VPN | Disconnected, неизменные данные обеих групп |
| Оба перехода при активном VPN | Stopping → подтверждённый cleanup → Disconnected нового источника; без автоподключения |
| Повторные быстрые нажатия / повторная IPC-команда | Нет двух sessions, нет обратного отката UI старым snapshot |
| Смена во время Connecting | Попытка отменена, owned процессы завершены, источник меняется только после baseline |
| Смена во время Disconnecting | Команды сериализованы, повторный cleanup идемпотентен |
| Error / CleanupError | При неуспешном cleanup старый источник сохраняется; после восстановления переключение повторяется |
| Пустая группа | Нет чужого fallback; connect не запускает core |
| Refresh каждой группы / ошибка одной | Ошибка и timestamp принадлежат своему ID/source; другая группа и её выбор не затронуты |
| Refresh пересекается со switch/delete | Результат не переносится в другую группу и не восстанавливает удалённую подписку |
| Restart Atlas | activeSource и оба выбранных сервера восстановлены из реального Store |
| После каждого системного перехода | SCM/owned PID state, TUN baseline, owned routes/WFP, DNS/proxy проверены независимо; прямой DNS/HTTPS отдельно от отсутствия ресурсов |

События `source_switch_started`, `source_switch_network_restored`, `source_switch_completed` связываются с существующими `command_*`/`shutdown_stage_*`/`recovery_baseline`. Credentials и URI в них не пишутся. Исходный VLESS-ключ не включается в репозиторий или отчёт.

PR, release и установка на рабочий компьютер в рамках этих изменений не выполнялись.
