# Разделение операций Atlas

Проверка исходников 28.09.2026. Изменения локальные; PR приостановлен.

## Сравнение с Mihomo

В используемой версии v1.19.29 `GET /proxies/{name}/delay` вызывает новый
`URLTest`. Он открывает соединение и записывает новый результат независимо от
предыдущего `alive`. `PUT /proxies/{name}` меняет селектор, не очищая историю
других узлов. Обновление подписки для повторной попытки не требуется.

Источники:
- https://github.com/MetaCubeX/mihomo/blob/v1.19.29/hub/route/proxies.go
- https://github.com/MetaCubeX/mihomo/blob/v1.19.29/adapter/adapter.go

## Проверенные пересечения

| Операции | Причина / правило разделения |
| --- | --- |
| Выбор сервера — отображение пингов | Общая revision и selected очищали всю таблицу. Теперь результат принадлежит имени и SHA-256 параметров конкретного узла. |
| Выбор сервера — фоновые URL-тесты | QueryJobs.invalidate отменял всё. Теперь сохраняются тесты конкретных серверов, отменяются зависимые от маршрута чтения и тесты групп. |
| Выбор сервера — IPC службы | Синхронный confirm_route удерживал канал на время внешних запросов. Теперь команда подтверждает локальный селектор через PUT/GET, а доступность проверяет монитор. WFP не меняется. Выбор недоступного сервера не означает подтверждённую доступность. |
| Подписка — результаты других подписок | updatedAt больше не является причиной очистки. Изменившиеся/удалённые узлы отбрасываются по идентичности; результаты неизменившихся сохраняются. Старые события изменённого узла не принимаются. |
| Загрузка подписки — App mutex | HTTPS вынесен за mutex; применяется короткая проверка актуальности перед записью. У каждой подписки собственный Lease, ошибка и время успешного обновления. |
| Пинг — оперативное чтение состояния | Разные лимиты QueryJobs; одинаковые незавершённые проверки объединяются, завершённая ошибка не используется для новой попытки. |
| Автовыбор — ручной выбор | Ручной выбор отменяет старый план восстановления. Это необходимая связь: старый план не должен отменить решение пользователя. |
| Карантин — ручной пинг | Ручная проверка не фильтрует карантин. Фоновое восстановление повторно проверяет карантинные узлы; успешная проверка возвращает узел в выбор. |
| Реальная замена конфигурации / остановка — незавершённые операции | Полная отмена сохраняется: старое ядро и изменённая конфигурация не могут выдавать актуальные доказательства. При полном reload Mihomo проверки могут прерываться; это локальная ошибка проверки, не доказательство таймаута сервера. |
| Выход — другие операции | Отмена соединения имеет приоритет; новые мутации отклоняются при ShuttingDown. Сетевые изменения и завершение сессии намеренно сериализованы. |

Это аудит перечисленных путей, не доказательство отсутствия всех возможных
гонок. Служба по-прежнему сериализует изменения сети; запуск, применение
конфигурации и восстановление содержат длительные операции. Изоляция ручного
выбора не заменяет дальнейший анализ этих путей при подтверждённых сбоях.

## Проверки

- Frontend: сохранение готового пинга и незавершённой проверки неизменившегося
  узла; отбрасывание результата прежних параметров изменённого узла.
- QueryJobs: смена выбора сохраняет незавершённый тест узла, отменяет групповую
  проверку и чтение старого маршрута; новая попытка получает новую работу.
- Реальный bundled Mihomo, отдельный loopback-контур без TUN: первый запрос
  теряет соединение, после восстановления второй успешен без обновления
  подписки и перезапуска ядра; между запросами меняется селектор.
- Существующие проверки: VLESS восстанавливается после перезапуска сервера,
  независимые клиенты, задержанные проверки, отмена предыдущей сессии,
  перезагрузка/откат конфигурации, завершение собственных тестовых процессов.

Рабочие адаптеры, DNS, proxy, WFP, служба и установленный Atlas для этой
проверки не изменялись. Причину прежнего офисного инцидента эти тесты не
устанавливают: если параметры узлов у провайдера изменились, обновление
подписки действительно нужно; если восстановился тот же узел, достаточно
нового URL-теста.
