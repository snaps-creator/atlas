Confirmed defects and fixes
1. core.apply_verified only restored top-level ATLAS after configuration reload.
   AUTO/FAILOVER reverted to their first listed node. An isolated instance of
   the identical Mihomo binary reproduced this with both stable and changed
   node names. Restore nested selection and verify it on apply AND rollback.
   When a subscription rotates the configuration digest, retain the logical
   name/source only if the candidate is unique. Never guess across sources or
   ambiguous matches; deleted nodes retain normal new-config selection.
2. Active monitor treated a single plain-HTTP endpoint failure as a dead node.
   Confirm remote failures using the HTTPS control before quarantine; apply
   the same confirmation to replacement candidates and old-path rechecks.
   Controller/local errors remain distinct and do not condemn remote nodes.
3. Subscription recovery consumed failures for abandoned nodes for 60 seconds,
   even after a healthy replacement was selected. Restrict recovery-triggered
   refresh to the currently selected terminal proxy. Periodic/manual refresh
   and genuine active-node failure recovery remain enabled.
4. Commit 495157b changed positional names to runtime-configuration digests.
   Rotating SNI/credentials therefore removes the selected name; subscription
   installation then changes a manual pin to AUTO. A fixture reproduces this
   for both migrated legacy names and new digest names. Remap active and saved
   source selections to the unique same logical node before checking presence.
   This proves a selection regression introduced in 2.4.2, not the cause of
   every initial network timeout. Duplicate candidates are never guessed.

Regression boundary / limitations
The top-level-only reload restoration already exists in 2.3.1 (4a6ed36).
It is a demonstrated defect, NOT a proven newly introduced 2.4.2 regression.
Installed previous/current Mihomo and Xray binaries have identical SHA256.
Generator modules from 2.3.2 (9d54431) and 2.4.2 generated identical output for
the same sanitized 186-node runtime-derived fixture and synthetic raw REALITY
transport: SHA256 17bbec0ed2ab2e4258e3842af85278a531bd265f384ddee3c820471adf2593ff.
This is generator parity for that fixture, not a previous-app runtime A/B.
The active subscription rotated REALITY SNI/shortId and node digests during
measurements. These changes prevent attribution to application version alone.
