# Atlas 2.4.2 transactional installer contract

The NSIS container carries `$PLUGINSDIR/payload/`, not a flat installed directory. It must contain:

| Role | Packaged implementation | Version rule |
|---|---|---|
| Desktop | Atlas.exe | Atlas 2.4.2, x64 |
| Service | Atlas.Service.exe | Exact app bytes, Atlas 2.4.2, x64 |
| Stable launcher | AtlasUpdater.exe, installed as root Atlas.exe | Atlas 2.4.2, x64 |
| Native updater | AtlasUpdater.exe | Atlas 2.4.2, x64; receipt-bound |
| Cleanup | AtlasMaintenance.exe | Atlas 2.4.2, x64 |
| VPN engines | resources/Atlas.Core.exe, resources/Atlas.Xray.exe | x64 and pinned resource-manifest hashes; upstream engine versions are independent of Atlas |
| CEF runtime | libcef/chrome_elf/EGL/GLES/D3D/Vulkan DLLs, pak/ICU/snapshot/locales | x64 DLLs; all bytes bound by native receipt |
| Geodata/licenses | resource manifests, geodata and license files | pinned Xray geodata hashes, receipt integrity |
| Defaults | Compiled into desktop; no external user credential/default profile | Bound by desktop hash |
| Service registration and migration | Native executable code | Bound by updater/app hashes |
| Uninstall | NSIS writes uninstall.exe at install time and invokes native cleanup | Not an expected prebuilt payload file |

The installed root launcher is generated by the supervisor copying AtlasUpdater.exe, not a missing AtlasLauncher.exe. The active desktop/service live under versions/<version-build>; current.json and the journal are created at installation. User configuration is retained, not bundled. The independent upstream engine/CEF version numbers must not be rewritten to 2.4.2.

Assertions check required roles, metadata, x64 machine type, pinned resources and native full-inventory receipt. The receipt's exact inventory is intentional integrity checking, not a hard-coded count of 32 files. Additional valid release files can be represented by a newly built receipt.

The identity test creates its own private copy, requires the packaged service for transactional payloads, verifies app/service equality, tests that actual packaged service, and removes only that private fixture. Legacy flat packages may still synthesize their historical service copy. An absent transactional service is never silently synthesized.
